# DSpark Benchmark Results

在 **8× NVIDIA A800-SXM4-80GB（SM80）/ TP8 / SGLang 0.5.16** 上，对两个 DSpark 参数组合执行完整对比测试。

## 测试配置

| 项目 | 配置 A | 配置 B |
|---|---:|---:|
| `--mem-fraction-static` | `0.85` | `0.90` |
| `--chunked-prefill-size` | `16384` | `32768` |
| `--max-running-requests` | `16` | `16` |
| `--speculative-algorithm` | `DSPARK` | `DSPARK` |
| Context Length | 1K / 4K / 16K / 64K / 128K | 相同 |
| Concurrency | 1 / 8 / 16 | 相同 |
| 每组请求 | 30 + 5 warmup | 相同 |
| 完整重复 | 2 | 相同 |
| Output Length | 1024 tokens | 相同 |
| Sampling | temperature=0, top_p=1.0, top_k=1, seed=42 | 相同 |
| 统计请求 | 900 | 900 |
| Error / Timeout | 0 / 0 | 0 / 0 |

## 核心结论

- 配置 B 在 **8/15** 个 Context × Concurrency 组合中获得更高聚合吞吐，配置 A 在 **7/15** 个组合中更高。
- 配置 B 在 **1K / C16** 平均吞吐提高 **+27.13%**，但两次重复波动达到 **19.73%**，应谨慎看待单点峰值。
- **16K** 档位配置 B 在 C1/C8/C16 分别变化 **+6.15% / +4.63% / +3.33%**。
- **128K** 档位配置 B 在 C1/C8/C16 均下降：**-10.98% / -7.61% / -7.85%**。
- 因此 `chunked-prefill-size=32768` 不是全场景更优；若服务包含大量 128K 长上下文流量，配置 A 更稳妥。若以中短上下文、高并发为主，可进一步验证配置 B 的波动后再选用。

## 指标口径

- **Gen Throughput**：本组所有成功请求的 completion tokens / 组墙钟时间。
- **Accept Rate / Accept Len**：只解析该组对应的 SGLang `Decode batch` 日志字节区间。
- **TTFT**：请求发出到首个非空流式内容事件。
- **TPOT / ITL**：首 token 后按 completion token 数归一化。
- **GPU Utilization / Memory / Power**：`nvidia-smi` 每 0.5 秒采样，GPU0–7 分别记录。
- **Peak VRAM**：本组 GPU0–7 的最高采样显存。

## 可复现性说明

测试脚本会校验服务进程中的 `mem-fraction-static`、`chunked-prefill-size` 和 `max-running-requests`，且未发现 AR/AL 时会直接停止，避免生成指标缺失的报告。输入 prompt 经本地 tokenizer 构造为精确的 1K/4K/16K/64K/128K token 档位，服务端 `usage.prompt_tokens` 同时记录到原始 JSON。
